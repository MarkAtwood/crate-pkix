All notable changes to `pkix-dane` are documented here. The crate
follows [Keep a Changelog](https://keepachangelog.com/) headings and
[Semantic Versioning](https://semver.org/).

## [Unreleased]

Planned release: **0.2.0**. Breaking relative to 0.1.0 only in the sense
that 0.1.0 had no public API at all.

### Added

TLSA record types, matching, and all four certificate usages
(PKIX-j32w.1). The crate is no longer a namespace reservation.

- **Record types** — `TlsaUsage`, `TlsaSelector`, `TlsaMatchingType`,
  each a total enum over all 256 octet values via `Unassigned(u8)` and
  `PrivateUse` variants, with `from_octet` / `to_octet` round-tripping
  every octet. Deliberately **not** `#[non_exhaustive]`: a `match` over
  a field is total, so security-critical matching code cannot silently
  omit a usage. The cost is that a future IANA assignment becomes a
  breaking change, which is the right trade pre-1.0.
- `TlsaRecord` — `from_rdata` / `to_rdata` for DNS wire format, field
  accessors, and `is_usable` implementing RFC 7671 §17 (unrecognized
  parameters) and §10 (digest-length mismatch). Unusable records are
  *skipped*, never fatal, so a domain can publish a usage this client
  does not understand alongside one it does.
- **Matching** — `PresentedCert`, pairing a certificate with the exact
  octets it arrived as; `selected_content`; `matches`;
  `matching_records`; and `matches_spki` for anchors held as a bare
  public key rather than a certificate.
- **The four usages** — `verify_dane_ee` (3), `verify_pkix_ee` (1),
  `verify_dane_ta` (2, returning a `DaneTrustAnchor` carrying the
  synthesized `pkix_path::TrustAnchor`, the authorizing record, and a
  `TrustAnchorSource`), and `verify_pkix_ta` (0).
- **Resolver seam** — `TlsaResolver` trait with a `batch_resolve`
  default impl, and the zero-cost `NoTlsaResolver` default. Synchronous;
  the async analogue belongs in `pkix-dane-resolver` behind its `async`
  feature, per the Option C placement settled in PKIX-a1yc.10.
- **DNSSEC status** — `DnssecStatus` (`Secure` / `Insecure` /
  `Indeterminate` / `Bogus`) with `is_secure` and
  `permits_pkix_fallback`, and `TlsaResponse` pairing records with the
  status they arrived under, plus `is_authenticated_denial`,
  `has_usable_record` and `records_for_usage`.
- `DaneError` — 14 variants, `#[non_exhaustive]`, hand-rolled `Display`
  matching the convention in `pkix-aia` and `pkix-revocation`.
- `TlsaName` / `TlsaProtocol` — RFC 6698 §3 owner-name construction
  (`_443._tcp.host`) with DNS label and length validation. Placed in
  this `no_std` crate rather than the resolver because it is pure string
  work with no I/O, and a caller supplying their own resolver needs it.
- Feature: `serde`. There is no `std` feature: `DaneError` implements
  `core::error::Error` unconditionally (Rust 1.81, below the workspace
  MSRV), and nothing else in the crate needs `std` — TLSA matching is
  pure computation over caller-supplied bytes.

### Design notes

- **Matching hashes received octets, never a re-encoding.** `x509-cert`
  0.3 normalizes a validity date before 2050 from `GeneralizedTime` to
  `UTCTime` when it re-encodes, so `to_der()` on a parsed certificate
  does not round-trip for such a certificate, and a digest over its
  output would not match the certificate's own correctly-published TLSA
  record. `tests/byte_exactness.rs` demonstrates the divergence on a
  hand-assembled fixture and asserts that matching succeeds over the
  received bytes.
- **Verify functions take `&TlsaResponse`, not `&[TlsaRecord]`,** so the
  DNSSEC check cannot be skipped. Unvalidated TLSA records hand
  certificate choice to whoever answers a DNS query.
- **Trust anchors are built with `TrustAnchor::try_from`, not
  `from_cert`.** The latter maps an unparsable `NameConstraints`
  extension to `None`, yielding an unconstrained anchor; failing closed
  (`DaneError::AnchorNameConstraintsMalformed`) is what RFC 5280 §4.2
  requires of an unparsable critical extension.
- **`verify_dane_ta` prefers the presented chain** over a record's
  embedded anchor certificate, reporting which applied through
  `TrustAnchorSource`.

### Testing

- 82 tests: 8 byte-exactness, 21 matching, 17 parsing, 24 trust-anchor,
  9 serde round-trip, 1 OpenSSL differential (12 verdicts compared
  inside it), 2 doc tests. Expected digests come from `openssl dgst` via
  `tests/fixtures/digests.txt`, generated by `tests/fixtures/gen.sh` —
  never from this crate's own hashing, which would prove only
  self-consistency.
- `tests/openssl_differential.rs` compares verdicts against OpenSSL's
  own DANE engine over the full selector × matching-type grid, driving
  `openssl s_server` / `s_client -dane_tlsa_rrdata` and reading
  `X509_V_ERR_DANE_NO_MATCH`. Skips with a printed reason where OpenSSL
  or a loopback socket is unavailable.
- `tests/fixtures/gen_gentime.py` assembles the `GeneralizedTime`
  fixture by rewriting a certificate's time fields, gated on an exact
  TLV round trip so a byte difference can only come from the intended
  edit.
